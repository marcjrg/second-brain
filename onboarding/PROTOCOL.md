# Guided onboarding protocol

1. Briefly introduce Second Brain: optional ambient/on-demand AI framework for projects, learning, private approved knowledge and structured assistance. Explain GitHub integration and that UI/tool availability varies. Ask whether to continue before mutations.
2. Offer five optional questions (accept defaults is allowed): activation always_on/on_demand; communication collaborative_instructor/concise/skeptical; proactivity quiet/balanced/proactive; saving suggest_and_approve/manual_only; primary uses projects/learning/knowledge/productivity.
3. Summarize the chosen values and intended private writes; request approval before creating a repository or persisting preferences. Never infer a selection merely because the recommended default was displayed.
4. Locate or create an authorized **private** workspace; verify owner, visibility, default branch, and read/write access. Use the template under `template/private/` and the schema at `schema/PREFERENCES.md`. If existing files exist, compare and preserve; do not overwrite without review.
5. Read back preferences and installation metadata. Generate a compact custom-instructions bootstrap with verified public contract, private repo and **direct preferences-file URL**, activation and shortcuts. Preserve existing user instructions. Distinguish generated from actually applied.
6. Explain !, ?, Modes → Save → Actions, and conversational fallbacks. Run checks from `tests/ACCEPTANCE.md`, and report verified/unverified capabilities separately.
7. Resuming setup must discover existing files, never blindly recreate or erase them. No public repository should receive personal data.
